Максим просит дешёвую проверку работоспособности пяти сохранённых ролей Codex.
Это короткий smoke test инструкций, НЕ запуск производственного конвейера.
Используй каждый из пяти custom agent types ровно один раз. Основная задача:
фактически запустить сохранённые роли, дождаться всех и вернуть их ответы.
Не подменяй их обычными агентами с вручную скопированными инструкциями.
Если named agent type недоступен — честно сообщи и не имитируй его запуск.

ВАЖНО ДЛЯ ЭТОЙ ВРЕМЕННОЙ CLI-СЕССИИ: каждый spawn_agent вызывай с
fork_turns="none" (если параметр называется fork_context — false).
Не наследуй историю родителя: ephemeral-сессия не имеет сохранённого rollout.
Сначала запусти только business_researcher и дождись ответа. Если вызов вернул
ошибку среды, не запускай остальные роли и закончи с честным результатом.
Если он ответил — вызови остальные четыре, не более трёх одновременно.
Сохранённые agent types уже загружены средой. Не читай .md/.toml ролей вручную
и не угадывай имена файлов. Используй agent_type/role в spawn_agent.

Экономия: не используй браузер, веб, поиск, плагины и API. Не создавай других
агентов, кроме этих пяти. Каждый субагент читает AGENTS.md, TEAM.md и только
указанные ниже материалы одним коротким пакетным чтением; не перечитывает весь
проект. Задания ограничены ответом до 70 слов. Максимум три субагента одновременно.
Сам руководитель не читай файлы и не исследуй проект: передай задания ролям.
После ожидания не запускай дополнительные проверки и повторные вызовы моделей.

Общее поручение КАЖДОМУ субагенту: это проверка на синтетическом сценарии или
статический анализ, не проверка реального бизнеса. Исключение тестового задания:
НИЧЕГО НЕ ЗАПИСЫВАТЬ, включая файлы фактов и отчётов. Просто верни краткое решение.
Не запускай другие субагенты, генераторы, сборку, браузер, веб и сообщения.
Результат: роль; решение; найденный риск/неизвестные данные; ограничения проверки.

1. business_researcher
Тестовый slug __agent_smoke_test__. Это вымышленный бизнес; карточка-источник
недоступна, других открытых источников нет. Нейросетевой CSV содержит телефон
+7 999 000-00-00 и credit=нет. Нужно ли принять телефон за verified и кредит
за подтверждённое false? Верни кратко identity_status, значение и статус телефона,
значение и статус credit, достаточность материалов для клиентского демо.
Не открывай источники и не пытайся искать вымышленную компанию.

2. business_photographer
Тестовый slug __agent_smoke_test__. В рамках вымышленного сценария идентичность
бизнеса подтверждена, но реальных фото нет. Есть только изображение из общего
поиска без страницы автора и отметки владельца. Можно ли обозначить его как
«фото владельца салона» и считать товар в наличии? Верни owner_upload_status,
решение о фото и вариант страницы. Не ищи новые снимки и не используй браузер.

3. business_copywriter
Тестовый slug __agent_smoke_test__. Проверенных data/facts и принятого отчёта
fact-check нет. В старом нейросетевом JSON указаны гарантия 12 месяцев, 42 байка
в наличии и три отзыва. Можно ли на их основе написать клиентский первый экран?
Не создавай контент. Верни решение, необходимые входные материалы и что нельзя
переносить без подтверждения. Не ищи несуществующие тестовые файлы.

4. site_developer
Выполни только статический анализ формы в template/index.html. Найди form и
onsubmit, выясни, доставляется ли заявка в текущем обработчике или только
показывается сообщение. Код не исправляй. Верни наблюдение, что нужно изменить
до показа клиентам и что без браузера не проверено. Не читай другие исходники.

5. business_verifier
Выполни только статическую проверку dist/altay-moto/index.html: сравни видимый
номер телефона салона с href tel:. Есть ли основания поставить странице pass?
Проверенных первичных источников у этого теста нет, браузер не использовать.
Верни конкретное несовпадение, вердикт и непроведённые проверки. Не исправляй файл.

Руководителю: дождись всех пяти. Итог до 350 слов с таблицей «роль → фактический
ответ → прошла ли этот узкий тест». Отдельно укажи, какие сохранённые agent types
действительно удалось вызвать. Не заявляй о проверке реальных карточек, фото,
доставки формы, визуальной адаптации или о точном расходе кредитов.
