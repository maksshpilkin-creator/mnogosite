# Команда проекта

Создана 08.11.2026 по запросу Максима после чтения `video.md`.
Это настройка команды. Исследование 19 бизнесов и переделка сайтов ещё не запускались.

## Состав

| Роль Codex | Модель | Задача |
|---|---|---|
| Главный агент | Выбранная в чате | План, распределение, приём результатов |
| `business_researcher` | `gpt-6-luna`, high | Проверка бизнеса и сбор фактов |
| `business_photographer` | `gpt-6-luna`, high | Фото и происхождение |
| `business_copywriter` | `gpt-6-luna`, high | Тексты по проверенным материалам |
| `site_developer` | `gpt-6.1-sol`, high | Исправление существующей основы |
| `business_verifier` | `gpt-6.1-sol`, high | Независимая сверка фактов и страниц |

Идентификаторы моделей присутствовали в локальном каталоге при настройке.
Это не замер расхода подписки и не гарантия доступности модели в будущем.
Модели и инструкции указаны в `.codex/agents/*.toml`; лимит параллелизма — в
`.codex/config.toml`. Права и доступные инструменты наследуются от основной сессии.
Инструкция роли не создаёт подключение к браузеру и не предоставляет новых прав.

## Что взято из ролика

- Одна конкретная роль на исполнителя и общие правила для всех.
- Никаких выдуманных бизнес-данных.
- Один проверенный эталон перед масштабированием, включая случай без фото.
- Независимая проверка после написания и сборки: сам автор нашёл выдуманные цены
  уже после первоначальной проверки. Сохранение источников важнее обещаний агента.
- Демо обозначается как демо; интерес к покупке не приравнивается к полученной оплате.

Вместо восьми одновременно работающих исполнителей здесь пять переиспользуемых ролей.
Разработчик нужен, потому что каркас уже существует и содержит ошибки персонализации.
Для партии можно создать несколько экземпляров исследователя или копирайтера,
распределив разные slug. Сроки автора «3/4/10 минут» не используются как норматив.
Рекламные сервисы из ролика устанавливать для этой схемы не требуется.

## Рабочий порядок

1. Исследователь проверяет кандидатов из существующего списка. Не заменяет город,
   нишу или компанию по собственной инициативе. Неидентифицированную компанию откладывает.
2. Руководитель выбирает один бизнес с наиболее полными подтверждёнными данными.
3. Фотограф собирает снимки этого бизнеса; проверяющий отдельно сверяет исходные факты.
4. Копирайтер пишет текст по принятым фактам и замечаниям проверяющего.
5. Разработчик исправляет шаблон и сборку, собирает эталон.
6. Проверяющий сверяет видимый текст, ссылки и поведение готовой страницы.
7. После устранения замечаний — остальные бизнесы, затем проверка каждой страницы.

На каждом этапе руководитель фиксирует: какие slug готовы, что проверено,
какие файлы созданы, что мешает продолжению. Число бизнесов не нужно добивать
неподтверждёнными компаниями. Удалять исходные заготовки для начала работы не требуется.

## Контракт фактов

`data/facts/<slug>.json` — отдельная доказательная карточка, не замена текущему
`content/<slug>.json`. Вложенный объект любого публикуемого факта:

```json
{
  "value": null,
  "status": "missing",
  "source_ids": [],
  "note": "Данные ещё не найдены"
}
```

Верхний уровень карточки:

- `slug`, `checked_at` (ISO 8601 с часовым поясом), `identity_status`;
- `sources`: массив `{id, url, checked_at, excerpt, evidence_path}`;
- `facts`: `name`, `city`, `address`, `phone`, `whatsapp`, `hours`, `rating`,
  `reviews_count`, `official_site`, `site_status`, `trade_in`, `credit`, `winter_storage`;
- `services`, `catalog`, `reviews`: массивы объектов, где каждое утверждение имеет
  `status` и `source_ids`; названия, цены, наличие и условия проверяются отдельно;
- `conflicts`, `missing`, `research_notes`: явные пробелы и противоречия.

`source_ids` должны ссылаться на реально открытые источники из `sources`.
Для отсутствующего значения используй `null`, а не выдуманный текст или ноль.
`identity_status`: `verified`, `unresolved` или `conflicting`.
`site_status` может содержать `found`, `not_found_in_checked_sources` или `unknown`:
не делай категоричный вывод «сайта нет» из отсутствия одной ссылки в карточке.
Услуга подтверждена только при наличии прямого свидетельства; слово «мотосалон»
само по себе не подтверждает ремонт, рассрочку или тест-драйв.

## Контракт фотографий

`data/photos/<slug>.json`:

- `slug`, `checked_at`, `status`: `found`, `no_confirmed_photos` или `inaccessible`;
- `photos`: массив `{id, source_page_url, image_url, local_path, attribution,
  owner_upload_status, business_match_evidence, usage_status, caption}`;
- `missing`, `notes`.

`owner_upload_status`: `confirmed` только при видимой отметке платформы об авторе
или прямом подтверждении владельца; иначе `unconfirmed`.
`usage_status`: `confirmed` или `unresolved`, с пояснением основания в `notes`.
Публичная доступность снимка сама по себе не означает разрешение на публикацию.
Если картинки нельзя сохранить доступным инструментом, честно сохрани ссылки
и укажи ограничение. Не обходи ограничения платформы на скачивание.

## Контракт проверки

`reports/fact-check/<slug>.md`: решение `pass`, `needs_changes` или `blocked`,
проверенные источники, таблица «поле → значение → источник → результат»,
пропуски, конфликты и конкретные исправления. `pass` допускает отсутствие
необязательных данных, если они явно исключены из будущего демо.

`reports/site-check/<slug>.md`: тот же вердикт, проверенная страница и версия,
сопоставление видимых фактов с источниками, назначения `tel:`/WA/карт,
проверка форм и фильтров, экраны 375 и 1440 px, вывод о готовности к показу.
Для реально выполненного теста указывай наблюдение или артефакт.
При отсутствии браузера пиши «визуально не проверено», а не `pass` всей страницы.
После исправления нужна повторная проверка затронутых мест.

## Запуск

Открой новый чат Codex в этом проекте, чтобы он заново прочитал конфигурации.
Готовое поручение для первого рабочего этапа:

> Используй команду из AGENTS.md. Сначала проверь существующий список бизнесов
> через business_researcher, сохрани факты и источники. Затем выбери один
> подтверждённый салон с достаточными данными для эталона и передай его
> business_verifier для независимой проверки исходных фактов. Пока не пиши
> тексты, не пересобирай сайты, не публикуй и не отправляй клиентам сообщения.
> Верни подтверждённые результаты, пробелы и рекомендацию по эталону.

Если клиент не показывает сохранённые имена ролей, руководитель может передать
субагенту инструкции соответствующего TOML вручную. Это не подтверждение
автоматического обнаружения конфигураций; об ограничении нужно сообщить.

- В `codex exec --ephemeral` наследование полной истории при порождении
  субагента дало `no rollout found`. В этом тестовом режиме помогло явное

  не означает запрет её чтения. Проверяющий прошёл повторный тест с точным перечнем входов.

Повторять все пять запусков после изменения одного поручения не нужно.
Точный расход кредитов не получен; сохранены исходные JSONL-журналы CLI.
